# dsh-price-peak

English | [中文](README.md) — [README.en.md](README.en.md)

**DeepSeek API 峰谷价格徽标** —— 在 DeepSeek Harness 的输入框上方常驻一行：当前
价格倍率（高峰 ×2 / 空闲 ×1）、判定所依据的**北京时间**、以及距离下次切换的倒计时。

```
×1   北京 02:52 · 国庆节假期 · 全天空闲      距高峰 3天6小时        ● 详情
```

点「详情」展开单价表（空闲 / 高峰两列）、高峰时段、数据来源与上次更新时间。

**它不做什么**（先说清楚，省得你装了才发现）：**不统计 token、不计算本次会话花费、
不读账户余额。** 它只回答一个问题——**「现在这一刻的单价是几倍？」**
需要逐条账单和余额的，去看 [j-chien/dsh-meter](https://github.com/J-Chien/dsh-meter)
或 [TwotwoPiggy/dsh-balance](https://github.com/TwotwoPiggy/dsh-balance)。

---

## 三个可能让它值得装的点

同类插件不少，所以先说差异 —— 以下都是**代码里可核对**的，不是形容词：

### 1. 价格表不是写死的，而是从官方页面解析出来的

`lib/core.js`、`lib/parse.js` 里**没有任何价格数字**（只有注释里举过例子）。
唯一的常量价格**表**是 `lib/snapshot.js` —— 一个 42 行的文件（测试里有价格断言，夹具里有页面原文，但都不是运行时的数据源），**没有**峰谷时段、
**没有**倍率，只在「首次运行」和「抓取失败」时兜底。其余文件里出现的 `offPeak`
都是**字段名**（读取、折叠、渲染），不是数值。

官方调价后，抓取到的值逐字段覆盖快照，**不需要等作者发新版**。
抓取带 `ETag` / `If-Modified-Since`，页面没变时只花一个 304。

### 2. 调休上班日按工作日算（这个坑很容易踩）

官方规则原文是「周一至周五（**不含中国法定节假日**）」。调休上班日（例如
2026-02-14 这个周六）**不是**法定节假日，所以它仍然算高峰。用「周一~周五」这种
朴素判断会把它算成空闲，**在你最省钱的那个周六告诉你现在是 ×1，而实际是 ×2**。

```
$ node preview.mjs --at 2026-02-14T10:00
  2026-02-14 10:00  ×2  高峰  调休上班日

$ node preview.mjs --at 2026-02-17T10:00
  2026-02-17 10:00  ×1  空闲  春节假期      [春节]
```

### 3. 北京时间是硬隔离的，你人在哪都一样

峰谷按北京时间定义。所有日历读取走固定 UTC+8，**从不**用本地时区 getter；
有一条测试在 `Asia/Shanghai`、`America/Toronto`、`UTC`、`Pacific/Kiritimati`
四个时区下对同一时刻断言输出**完全一致**。在多伦多看到的「北京 02:52」和在上海看到的
一模一样。

## 抓不到数据时会怎样

**按字段降级，并把来源摊开给你看**，而不是糊过去。价格表、峰谷时段、倍率分别解析、
分别回退，所以可能出现混用：

```
数据来源   价格：内置快照；峰谷时段：官方定价页；倍率：官方定价页
⚠ 价格表来自内置快照，不是本次抓取的结果。
```

最需要小心的是第二种：内置快照**不含**峰谷时段，所以页面脚注一旦解析失败，时段会退回
代码里的默认值（9:00-12:00 / 14:00-18:00）。官方若调整时段，这个假设不会被自动更新 ——
界面会明说，而不是继续标榜「官方定价页」：

```
数据来源   价格：内置快照；峰谷时段：代码默认；倍率：代码默认
⚠ 峰谷时段、倍率无法从页面确认，正在使用内置默认值；官方调整后这里不会自动跟上。
```

无论如何，**面板不会消失**：抓取失败会保留上一次结果、把圆点转黄，并在详情里写明失败原因。
圆点变黄有两种原因 —— **抓取失败**（立刻），或**数据超过 15 小时没更新**（`360 分钟 × 2.5`）。
两个条件都看，所以断网时不会出现「绿的、看着很新鲜」的假象。

## 为什么时间是北京时间

峰谷时段是按北京时间定义的，所以显示和判定都固定在 **UTC+8**：

- 所有日历读取都走 `Date.UTC` 加固定 +08:00 偏移，**从不**用本地时区 getter；
- 北京全年无夏令时，不需要处理 DST；
- 有一条测试在 `Asia/Shanghai`、`America/Toronto`、`UTC`、`Pacific/Kiritimati`
  四个时区下对同一时刻断言输出完全一致。

所以在多伦多看到的「北京 02:52」和在上海看到的完全一样。

## 为什么价格能跟着官方变

```
官方定价页 ──fetch(ETag)──► parse.js ──► 覆盖 ──► core.js ──► /price-peak/state ──► 面板
                                │                    ▲
                                └── 失败则保留上一次    └── snapshot.js 兜底
```

- **价格表、高峰时段、倍率、规则文字都从页面解析**，不是写死在代码里。
- 解析器读的是渲染后的**表格文本**而不是样式，所以换配色换布局不影响；
  但表格若重排，`parse.js` 需要更新 —— `test/parse.test.mjs` 用的是真实抓取的
  页面快照，**冻结**在抓取那一刻。它不会自己感知上游改版 —— 需要有人重新抓取
  （见「上游维护点」）。
- **唯一需要人工跟进的表：法定节假日日期。** 定价页公布了规则（"不含中国法定节假日"）
  但不公布日期，国务院每年单独发通知。内置了 2026 年的 33 天和 6 个调休上班日，
  可通过 `holidays` / `customHolidayRuns` 配置替换，无需改代码。

## 部分解析失败时会发生什么

页面解析是**按字段独立**的：价格表、峰谷时段、倍率分别提取，各自回退。所以可能出现
「价格来自内置快照、峰谷时段来自页面」这种混用状态。**不处理就会静默出错** ——
数据看起来是当前的，实际是两个来源拼的。

因此 `resolvePricing` 为每个字段记录来源（`live` / `snapshot` / `default`），界面据此显示：

```
数据来源   价格：内置快照；峰谷时段：官方定价页；倍率：官方定价页
⚠ 价格表来自内置快照，不是本次抓取的结果。

数据来源   价格：内置快照；峰谷时段：代码默认；倍率：代码默认
⚠ 峰谷时段、倍率无法从页面确认，正在使用内置默认值；官方调整后这里不会自动跟上。
```

第二种状态尤其重要：内置快照**不含**峰谷时段，所以一旦页面注释解析失败，时段就退回代码里的
默认值（9:00-12:00 / 14:00-18:00）。官方若调整时段，这里不会自动跟上 —— 面板必须说清楚，
而不是继续标榜「官方定价页」。

## 一个容易搞错的地方：调休上班日

官方规则只排除**法定节假日**。调休上班日（如 2026-02-14 这个周六）**不是**法定节假日，
所以按字面规则它仍按工作日计峰谷。默认 `treatAdjustedWorkdaysAsPeak: true` 遵循这个读法。

这个坑的连带后果：2026-02-14 这天 18:00 结束高峰后，紧接着是 9 天春节加周末，
**下一次高峰在 10 天后的 02-24 09:00**。倒计时逻辑因此按 14 天视界搜索切换点，
并且时长会显示成「9天14小时」而不是「230小时22分」。

## 开发说明

### 为什么产物 `lib/client.js` 入库

dsh 启动时加载的是**已构建**的客户端 bundle，所以克隆下来必须能直接装。忽略它会
让每个用 GitHub 的人拿到一个要自己发现构建步骤才不报错的插件。

代价是"生成物可能和源码漂移"。这一点由 `build.mjs --check` 兜住：产物与 `src/`
不一致时它会失败。注意它在 `npm run verify` 里，**不在** `npm test` 里 ——
`npm test` 只跑 `node --test`。提交前跑 `npm run verify`。

### 为什么构建是"包装"而不是"编译"

浏览器半区是纯 JavaScript，唯一的运行时依赖是 `react`，而它由 shell 作为平台模块
注入。所以 `build.mjs` 只做三件事：读取模板、内联样式表、套上
`window.__ModuleLoader__.load({ id, factory })` 外壳——和官方
`@deepseek-ai/dsh-client-ui-goal` 的产物同一形态。没有 bundler，因此产物可以直接
用眼睛审。

### 改代码时的几个约束（都是真机上踩出来的）

| 约束 | 原因 |
|---|---|
| 客户端 bundle 必须导出 `apply` 和 `inject` | 这是 Cordis 加载器认的插件面；写成 `define` 之类的自定义入口不会被调用 |
| 不要依赖 `styles` 服务 | 250 个已装包里没有任何客户端 bundle 用它；官方做法是把 CSS 内联进 bundle，用 `document.createElement("style")` 并在 `ctx.effect` 的清理函数里移除 |
| 宽度必须自带有效兜底 | `max-width: calc(var(--token) - 32px)` 在变量缺失时**整条声明失效**，元素会铺满整行 |
| 日历只能走固定 UTC+8 | 峰谷按北京时间定义，用本地时区 getter 会让你在多伦多看到错的判定 |
| 调休上班日算工作日 | 官方规则只排除法定节假日 |

### 加功能

- **新数据源**：改 `lib/parse.js`，并往 `test/fixtures/` 放新页面的真实快照。解析器
  测试跑的是真实 HTML。上游大改后，**重新抓取夹具**是让测试重新有意义的步骤；
  在此之前测试仍然通过，这是已知的盲区。
- **新界面元素**：改 `src/client.template.js`，然后 `node build.mjs`。
  `node preview-ui.mjs --open` 可以不装就看外观。
- **新配置项**：加到 `lib/index.js` 的 `Config` schema 和 `install/cordis.patch.yml` 注释里。

### 上游维护点

官方定价页改版会让 `lib/parse.js` 失效。**测试不会自动发现**：夹具是冻结的快照，
没有 CI，没有抓取脚本。发现途径是面板显示的来源变成「内置快照 / 代码默认」，
或者你自己重新抓一次夹具（见下）。
法定节假日日期每年需人工更新（见「已知限制」）。

### 两种预览的区别

| | 看什么 | 怎么用 |
|---|---|---|
| `preview.mjs` | **数据与判定**：倍率、峰谷、切换倒计时、节假日分类 | 终端命令；`--fetch` 会真的抓官方页面 |
| `preview-ui.mjs` | **外观**：信息条与详情面板的排版、配色、深色模式 | 生成独立 HTML，浏览器打开；不需要安装 |

界面预览页含 7 个场景：高峰 ×2、空闲 ×1、展开详情、数据过期（圆点转黄）、
来源混用、时段退化为代码默认、接口不可用（×?）。配色与圆角取自已安装的 `@deepseek-ai/dsh-client-ui-theme`，
输入框几何值取自 `dsh-client-ui-conversation`（卡片 `min(calc(100% - 16px), 952px)`、
内缩 8px）。类名映射直接从组件源码抽取 —— 改名会让预览显示异常，而不是悄悄失真。

**这个预览页已经赚回成本了**：它抓出一个真布局 bug —— `.dppDock` 一开始写成
`display:flex`，而 flex 默认 `row`，导致详情面板和信息条**并排**而不是上下堆叠。
对齐参考实现 `dsh-client-ui-goal` 的 `.dock` 后修正。这个 bug 看代码发现不了，
装进 App 才会看见。

## 宽度上的两个陷阱（真机上踩到的）

`.dppBar` / `.dppPanel` 用的是一个**绝对的**上限：`max-width: min(920px, 100%)`。

一开始它们跟随 `--dsh-composer-card-max-width`（即对话内容列宽），踩了两个坑：

1. **`max-width: calc(var(--token) - 32px)` 在变量缺失时整条声明失效**，`max-width`
   退回 `none`，元素直接铺满整个窗口。
2. **依赖外层列宽的变量不可靠。** 在约 2300px 宽的窗口上实测，信息条铺了约 2220px，
   而输入框卡片只有几百 px。槽位渲染在哪里不由本插件决定。

内容列宽按官方定义是 `clamp(680px, 对话列宽 × 0.64, 920px)` —— 上限本就是 920px，
所以现在直接用这个上限，`min(920px, 100%)` 同时保证有界和永不溢出。

`.dppDock` 的列宽沿用 goal bar 的公式（clearance 与 inset token），这些 token 都带了
兜底值，因为一个缺失的变量不能连累宽度。

## 已知限制

- **法定节假日表只覆盖 2026 年，且不会自我修正。** 到期后，落在工作日的法定节假日会被
  算成高峰 ×2（例如 2027-01-01 是周五、是法定节假日，却会被判为工作日高峰）。这**不是**
  刷新能解决的问题 —— 抓取只能拿到规则，拿不到日期。所以：
  - 面板会显示警告，说明当前日期已超出内置表覆盖范围，需要你在配置里补上当年的日期；
  - 数据同时被标记为过期（圆点转黄），因为此时判定不可信；
  - 国务院公布 2027 年安排后，用 `customHolidayRuns`（可带 `year` 字段）或无 `year` 的
    `holidays` 填入即可，无需改代码。
- **闰年按真实日历处理。** `2028-02-29` 会被接受，`2027-02-29`、`2026-02-29` 会被拒绝；
  超出一个月的假期区间会在当月最后一天停止，不会溢出到下个月。
- 定价页若大改表格结构，解析器需要更新。**测试不会自动报警**（夹具冻结、无 CI），
  要靠你重新抓取夹具，或注意到面板的来源标注变成了「内置快照」。
- **只支持中文定价页。** 英文页的标签不同（`MODEL`/`PRICING`/`Beijing time`），
  解析器会返回空，所以它**不是**兜底来源 —— 代码里也已不再尝试它。
  要支持英文页需要补标签映射和货币字段（英文页的报价是美元，而界面写死人民币）。
- 面板每秒轮询一次本地路由（数据 < 4 KiB，有测试守着上限）；介意后台开销的话
  调大 `src/client.template.js` 里的 `POLL_MS` 后重新构建。
